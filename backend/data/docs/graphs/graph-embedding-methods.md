# Graph Embedding Methods

**Graph Embedding** is a way to convert high-dimensional, sparse graphs _(where nodes are connected in complex ways)_ into low-dimensional, continuous vector spaces. Essentially, we are packing every node's properties and relationships into a compact list of numbers so standard machine learning tools can easily process them.

We do categorize the methods into three main families:

## 1. Vector Point-Based Methods

The core idea here is to take a high-dimensional graph _(where connections can be messy and sparse)_ and project the nodes into a low-dimensional "latent space". In this new space, every node is represented as a dense, continuous vector, and nodes that were "close" in the original graph remain close in the latent space.

There're three main types:

### 1.1. Matrix Factorization-Based

Those are Methods like **GraRep** and **HOPE** that work by **factorizing the adjacency matrix**. At its core, this approeach treats graph embedding as a data compression problem. We start with a massive grid _(the adjacency matrix or a similarity matrix)_ that represents all the connections in the graph, and we try to "factor" it into smaller, more manageable pieces.

1. **The Steup: The High-Dimensional Matrix**: Imagine we have a social network with $10,000$ users. To represent this perfectly, we could create a $10,000 \times 10,000$ matrix _(adjacency)_ where $1$ indicates a friendship and $0$ indicates no connection.
   - **The Problem**: This matrix is huge ($|V|^2$ space cost) and mostly filled with zeros (sparce). Using it directly for machine learning is computationally expensive and inefficient.

2. **The Process: Factorization**: Matrix factorization techniques take this large matrix and approximate it as the product of two much smaller, dense matrices.

   $$
   A \approx Z \times Z^T
   $$

   Here, $Z$ is our new "Embedding Matrix". If we set our embedding dimension to be small _(e.g., $128$)_, $Z$ is now only $10,000 \times 128$.
   - **The Result**: Each row in $Z$ becomes the low-dimensional vector representation for a specific node. These vectors preserve the graph's structure because multiplying them back together roughly recreates the original graph connections.

3. **The "Flavors": GraRep and HOPE**: While the basic idea is the same, these methods differ in _which_ matrix they factorize to capture different types of relationships:
   - **GraRep**: Focuses on **global structural information**. Instead of just looking at direct neighbors (1-hop), it constructs matrices based on k-step transition probabilities _(how likely you are to reach node B from node A in k steps)_.
   - **HOPE _(High-Order Proximity preserved Embedding)_**: Designed to preserve **asymmetric transitivity**. In directed graphs _(like X, where following isn't always mutual)_, the direction matters. HOPE consructs and factorizes a high-order proximity matrix that respects these directional flows.

:::caution The Bottleneck
The main limitations of these methods are:

- **Scalability Issues**: These methods cannot easily scale up to large network embeddings. They often rely on adjacency matrix-based measures, which have a high computational complexity of $O(|V|^2)$.
- **Overfitting**: The embeddings generated by these methods tend to overfit the adjacency matrix of the original graph.
- **Performance on Downstream Tasks**: Because of the overfitting, they generally do not work well on tasks like detecting inconspicuous connections, such as in link prediction.
- **Lack of Uncertainty Quantification**: As these are types of "Vector point-based" methods, they share the general drawback of not capturing important network uncertainty information.

:::

### 1.2. Random Walk-based

The shift to **Random Walk-based** methods marks a major turning point in graph embedding. These methods were developed specifically to address the scalability issues we just discussed with matrix factorization.

The core analogy:

- **In NLP**: We have sentences composed of words. The model learns that "bank" and "money" are related because they often appear near each other in the same sentences.
- **In Graphs**: We don't have "sentences", so we create them! We start at a node and take random steps to neighbors. This sequence of nodes _(e.g., $v_1 \rightarrow v_2 \rightarrow v_3 \rightarrow v_4$)_ is our "sentence".

The two main players in this category are:

1. **DeepWalk**: This was the pioneer. It uses simple truncated random walks. It treats every neighbor as equally likely to be visited next. It excels at capturing first-order proximity (local connections).
2. **Node2Vec**: This is an evolution of DeepWalk. It noticed that simple random walks might miss global structural patterns (like roles or communities). To fix this, it introduces biased random walks.

:::info The node2vec Strategy

Biased WalksNode2vec introduces two parameters, $p$ and $q$, to control the walker's behavior.

- **Breadth-First Search (BFS)**: Exploring immediate neighbors (micro-view).
- **Depth-First Search (DFS)**: Wandering far away from the start (macro-view).

The paper explains that by tuning $p$ (return parameter) and $q$ (in-out parameter), node2vec can switch between these two behaviors.

:::

### 1.3. Deep Learning-based

**SDNE** _(Structural Deep Network Embedding)_ represents the third branch of **vector point-based methods**. The key characteristics of these deep learning-based approaches:

- **The Architecture**: Instead of factoring a matrix or simulating random walks, these methods use **deep neural networks architectures** to perform the embedding.
- **The Goal**: Just like other methods we discussed, the goal is to project high-dimensional graph nodes into a low-dimensional, continuous vectors in a latent space.
- **The Advantage**: Along with random walks methods, these are preferred over matrix factorization because they are **scalable**. They typically have a computational complexity of $O(N)$ _(linear with the number of nodes)_ or similar, whereas matrix factorization can scale poorly at $O(|V|^2)$ or similar high costs.

However, even though SDNE uses advanced deep learning, it is still a **vector point-based method**. This means it sstill maps each node to a single, deterministic point in space.

---

All vector point-based methods lack **uncertainty quantification**, which means they are **overconfident**. They give us a precise coordinate for every node, but they don't tell us how reliable that coordinate is.

Here is a breakdown:

1. **The "Point" Problem**: In methods like DeepWalk or Node2Vec, every node is mapped to a single, specific dot in the vector space.
   - **The Issue**: Mathematically, a dot has no size. It implies $100\%$ precision.
   - **The Reality**: Real graph data is messy. Some nodes clearly belong to a specific group _(low uncertainty)_, while others are ambiguous or connect multiple groups _(high uncertainty)_. A simple dot looks the same in both cases.
2. **Homogeneity vs. Heterogeneity**: Uncertainty is directly related to the node's neighbors:
   - **Homogeneous Nodes**: If a node connects mostly to similar neighbors _(e.g., a student who only hass friends in the Math department)_, we should be very sure of its position.
   - **Heterogeneous Nodes**: If a node connects to very different communities _(e.g., a student with friends in Math, Drama, and Sports)_, its position is "fuzzier". Vector methods force this node to pick a single paverage spot, losing the nuance that it actually belongs to _multiple_ areas.

This is the main setup for the **Gaussian Distribution-based Methods**. Instead of a dot, they represent a node as a "cloud" or "soft region" _(a probability distribution)_.
